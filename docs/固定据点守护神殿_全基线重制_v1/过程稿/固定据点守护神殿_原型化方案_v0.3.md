### 1.3 已知坑与对策【已确认】

历史会话标题本身就是踩坑记录：

| 历史会话 | 含义 | 对策 |
| --- | --- | --- |
| 修复实体过多导致移动碰撞异常 | 大量实体时碰撞/移动出错 | 全部查询走 SpatialHash；软上限超限延后批次，不删怪、不改规则 |
| 修复实战卡死问题 | 战斗中卡死 | 生成与查询设每帧预算；寻路重算走增量队列，不整帧全量重算 |
| 优化 UI 文字与天赋选择 / 隐藏非实机界面按钮 | UI 信息密度与调试入口治理 | 守核界面信息优先级：核心危险 > 预警 > 因果反馈 > 掉落庆祝 |
| 探索游戏独创性玩法 | 曾尝试找差异点 | 本案的差异点已确定：固定核心 + 时间经济（P1 阶段就先立住） |

### 1.4 结论

**基底已经把「战斗演出 + 成长 + 存档 + UI + 性能」做完了；本案要写的，是战斗层之外的东西**——核心、路径、槽位、区域、终局。因此原型不是重写项目，而是在既有骨架上换一套「目的」。

## 2 参考项目策略吸取（元气骑士·守护神殿）

### 2.1 结构层策略【已确认】

固定神殿与魔法石（被毁即结束）→ 波次进攻 + 波间探索 → 据点房间（森林/冰川/火山，房间比常规关卡更大）→ 机械大师用紫币购买与升级防御塔、免费扳手、解救 NPC 得 15 紫币 → 每 5/10/15…波获得天赋 → 掩体可被修复 → 外星突变怪携带特殊能力 → 星币只从外星怪获得。

### 2.2 玩家策略 → 设计含义

| 玩家实际怎么玩 | 说明什么 | 本案取舍 |
| --- | --- | --- |
| 速刷蓝币 / 挂机流（固定武器、2–3 波升一次级） | 数值曲线可被碾压，存在「一套解」 | 加**上限**与**反套路**：速清奖励封顶、塔有克制、不能一塔通关 |
| 开荒有固定顺序（先放特定 NPC／据点） | 前期资源路径存在最优解 | 三条探索链各自有独立动机，不给唯一最优链 |
| 跳过剧情会导致武器不升到 +6 | 奖励与演出被耦合 | **解耦**：跳过演出不损失任何奖励与成长 |
| 买塔与救援绑定（紫币来路固定） | 探索产出建造资源 | E2 探索货币：只能从据点/远征获得，有上限 |
| 据点房间更大、地图布局焕新 | 地图是玩法容器 | E3 大地图：主殿 + 三片主题区 |
| 掩体可回血 | 防御设施是消耗品而非一次性 | 设施独立生命 + 战备修复（沿用 v0.1） |

### 2.3 反面清单（明确不做）

1. 不采用速刷/挂机经济目标；
2. 不复刻其地图、数值与怪物配置；
3. 不引入「跳过剧情就吃亏」的耦合；
4. 不引入移动据点、推车或护送逻辑（v0.1 已排除）。

## 3 脱离参考项目的边界

### 3.1 直接继承【复用】

SpatialHash、PerfQuality + FPSMonitor、SaveData + I18n、HUD/Minimap/DamageNumber 框架、音频与掉落框架、GameMode 单机标志。

### 3.2 改造后继承【改造】

| 原系统 | 现状语义 | 原型语义 |
| --- | --- | --- |
| Wave.lua | 时间推进 + 围绕玩家刷怪；玩家碾压时**加速刷怪**（×0.10/0.25/0.70，最低 0.05s） | 三路固定入口的生成队列 + 错峰；**把「碾压加速」替换为「速清奖励」**：`R = clamp(B − T, 0, 15s)`，奖励探索时间且不结转 |
| Enemy/Projectile | 目标只有玩家 | 目标优先级：核心 > 设施 > 角色；单位带 `wave_id` / `zone_id` 身份 |
| MapVariant | 单张竞技场 + 圆形障碍 | 多区域大地图；障碍支持方柱/墙体；新增可建造槽位与封路检测 |
| meta 图腾/符文 | 玩家词条与共振 | 设施词条、升级分支、邻接联携的数据基底 |
| 挑战模式修正器 | 敌人倍率、Boss 间隔 | 考验波 / 远征的难度变体钩子 |

### 3.3 必须新写【新写】

1. **固定核心与耐久结算**：位置固定、独立耐久、失败优先级（同帧失败 > Boss 死亡；有害反应结算完才判成功）；
2. **寻路 / 流场**（基底没有，因为 survivor 不需要）：三路到核心的流场、可建造阻挡、封路检测与重算回退；
3. **建造槽与设施**：槽位分级、设施独立生命、升级二选一分支、拆除返还 50%；
4. **区域与据点状态机**：未进入 → 激活守军 → 清空 → 奖励已领取 → 可布防；
5. **速清奖励结算**：波次结算面板 + 探索窗口计时与不结转规则；
6. **考验波（E4）与大地图（E3）**：多源向心出兵、区域解锁链；
7. **大远征（E5）与房间限伤**：逐房间推进、每房间对核心伤害上限 `C_room`。

### 3.4 命名与素材

- 项目名暂定「固定据点守护神殿」；**不沿用**「emoji 幸存者 / 咸鱼罐子」的命名与世界观；
- 原型期可继续用 emoji 作占位美术（省成本），但**语义要新做一套**（例如核心、据点、设施、远征队的图标），避免与基底怪物语义混淆；
- 基底素材如需借用，先在 `docs/ASSETS.md` 确认许可与来源，不默认可用。

## 4 原型分阶段设计（M0–M4）

### 4.1 主循环

```
章节选择 → 开场演出（可跳过，不损失奖励）
   → 战备/探索（基础 15s + 上一波速清奖励 R，≤30s）
   → 预警 ≥8s → 波次进攻（基准攻击时间 B）
   → 清波结算（生成完成 + 存活=0；有害反应须结算完）
   → 规则奖励：资金 / 经验 / 探索时间
   → 循环至 W20 → Boss 清空 → 考验波（E4）→ 大远征（E5）
   → 胜利 / 失败（角色或核心归零，立即失败）
```

### 4.2 数据模型（最小字段）

| 对象 | 字段 |
| --- | --- |
| core | `pos`、`hp`、`maxHp`、`anchored=true` |
| zone | `id`、`name`、`state`、`unlock_after[]`、`guard_pool`、`claimed` |
| slot | `id`、`kind`(主殿/走廊/据点)、`pos`、`facility_id` |
| facility | `id`、`type`、`level`、`branch`、`hp`、`coverage`、`anchored=true` |
| wave | `id`、`portals[]`、`base_combat_time`、`spawn_queue`、`offers` |
| expedition | `teams[]`、`route[]`、`dwell_time`、`room_cap`、`damage_done[]` |
| run | `wave`、`funds`、`sand`、`level`、`xp`、`explore_earned`、`explore_used`、`trial_done` |

### 4.3 阶段与通过标准

| 阶段 | 内容 | 通过标准（DoD） | 不做 |
| --- | --- | --- | --- |
| **M0 骨架** | 固定核心 + 1 条入口 + 1 种敌人 + 自动攻击/击退；接 SpatialHash 与性能档位 | 打得起来、能输能赢、60FPS 稳定 | 不做第二入口、不做成长 |
| **M1 守核闭环** | 三入口 + 流场寻路 + 核心耐久 + 暂停/重试 | 三路都能寻路到核心；失败与暂停语义正确 | 不做据点与地图外圈 |
| **M2 波次节奏（E1）** | 基础间隔、基准攻击时间、速清奖励结算、预警计时 | `R = clamp(B−T,0,15)` 可复现；奖励不结转、不可刷 | 不做数值平衡 |
| **M3 构筑（E2）** | 槽位 + 2 族设施 + 1 条升级分支 + 拆建与返还 + 覆盖显示 | 设施不封死路径；三套开局差异成立 | 不做全 4 族 |
| **M4 终局（E3/E4/E5）** | 大地图三片主题区 + 考验波多源向心 + 大远征与房间限伤 | 每房间伤害 ≤ `C_room` 可在日志验证；地图确实被复用 | 不做多章节 |

### 4.4 与 v0.2 的数值口径

E1–E5 的数值一律沿用 v0.2 表：`B0=15s`、`B(w)=30/45s`、`R_max=15s`、窗口上限 30s；`C_room = 核心耐久 8%–12%`。原型只验证**规则成立性与可读性**，不追求平衡。

## 5 技术护栏与性能预算

1. **空间索引**：碰撞、索敌、爆炸、限伤判定全部走 SpatialHash；单帧查询次数设预算上限；
2. **软上限**：同屏进攻怪建议 80；超限延后批次，不删怪、不提前清波；
3. **寻路预算**：流场增量更新，只在设施变动/区域解锁时整片重算；单帧重算面积封顶；
4. **画质档位**：沿用五档；性能紧张先降粒子与合并音效，**结算与规则不得被静默截断**；
5. **结算去重**：死亡/掉落/清波/奖励各只执行一次，`root_action_id` 贯穿连锁（对应 v0.1 的 R4/R6）；
6. **身份分离**：波次进攻怪、据点守军、远征队三类计数互不污染（R7）。

## 6 验收清单

### 6.1 技术验收（新增）

| 场景 | 预期 |
| --- | --- |
| 实体峰值（80+ 单位 + 弹体 + 掉落） | 帧率不低于目标，且碰撞/索敌结果正确（不出现「实体过多导致移动碰撞异常」） |
| 连续 20 波无卡死 | 无单帧长卡；寻路与生成均在预算内 |
| 暂停 / 失焦 / 演出跳过 | 全部模拟冻结；恢复后顺序与计时连续 |
| 存档中断续玩 | 局内状态（波次、资金、设施、区域、探索时间）与局外记录均正确 |
| 设施变动 | 流场增量重算；封路被检测并回退，敌人不会卡死 |

### 6.2 玩法验收

沿用 v0.2 第 12 节全部条目（速清奖励、考验波触发、大远征限伤、失败再开新局等），不重复展开。

## 7 实施路线与风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 寻路是全新模块 | M1 可能超期 | M0 先做单路直行验证，M1 再上流场；必要时先用「入口—核心」直线走廊 |
| 设施能封路 | 敌人卡死、寻路抖动 | 封路检测 + 流场重算 + 超时迁回合法点（v0.1 已有条款） |
| 大地图拖垮性能 | 帧率崩 | 区域分块 + 视口裁剪（MapVariant 已有范式）+ 软上限 |
| 核心耐久平衡 | 一局过难或过易 | 把「修复/设施/探索」三条减伤路径同时打开，数值后置 |
| 复用引入历史坑 | 碰撞/卡死复发 | 全查询走空间索引；不直接复用旧刷怪逻辑，只复用数据结构与工具 |
