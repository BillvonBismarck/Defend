# 第一部分 · 大构筑：双池技能树

## 1.1 目标结构

```
角色池 RP（人）                              炮台池 TP（设施）
├ 通用线：single / area / control /           ├ 8 设施 × 2 分支 × 2 级 + 专精
│           survival / mobility / defense     │   （rapid·area·slow·repulsor·
├ 角色线：所选角色的 3 段专属线 + 觉醒         │     barricade·stakes·repair·energy）
└ 与炮台池的协同节点（两池都点才生效）         └ 每个设施绑定一位 emoji 角色作为"守护灵"
```

- **升级 = 1 点 RP**：`Progression` 的十技能不再是随机三选一，而是树上的可点节点；`Options()` 从「抽 3 个」改为「按树规则返回当前可点的候选（仍保留 `UpgradeOffered/UpgradeChosen` 事件名与暂停源 `upgrade`）」。
- **据点/考验/远征 = TP**：首清据点 +2、每 5 波 +1、考验波 +1、远征结算 +1（合计 ≈20 点）。
- **加点不可逆但可洗**：洗点只在战备期、费用 `10 + 5×次数` 星砂（与现有 `irreversible_branches` 的"分支不可逆"并存：**洗点=退回点数，不退还已建分支的星砂**）。

## 1.3 炮台树（8 设施 × 守护灵 × A/B 双分支）

每个设施绑定一位 emoji 角色作为「守护灵」——**角色在幸存者模式里的战斗表现，就是这座设施的两种打法**：

| 设施（代码 ID） | 守护灵 | 分支 A（现有模块 ID 可直接沿用） | 分支 B | 专精（第 3 点） |
| --- | --- | --- | --- | --- |
| 速射塔 `rapid` | 小猫咪 😺 | **鱼骨连射**（= `rapid_sweep`，穿透 +1，伤害 ×0.8） | **重点锁定**（= `rapid_focus`，优先精英/远征主敌） | A：鱼骨暴雨（穿透 +2，命中弹射一次）／B：处决标记（对 30% 以下目标 +40%） |
| 范围塔 `area` | 黄豆勇士 😆 | **集群爆破**（= `area_cluster`，溅射 +0.8） | **聚焦爆破**（= `area_focus`，溅射 ×0.6、伤害 ×1.3） | A：连环豆雷（爆点再留 1 颗小雷）／B：豆芽陷阱（射程边缘埋雷，踩中爆炸 + 击退） |
| 减速塔 `slow` | 自然之灵 🍃 | **广域控制**（= `slow_field`，范围 +1.5、减速 −10pp） | **定点锚控**（= `slow_anchor`，范围 −1、减速 +10pp） | A：霜瑟风暴（3 层冻结 1s）／B：藤蔓锁定（对已减速目标 +40% 伤害） |
| 击退台 `repulsor` | 灵猴大圣 🐵 | **连击拳**（击退后弹射到 1.5 格内下一个目标，逐跳衰减） | **分身推掌**（同一次攻击对范围内 2 个目标各推 0.6×） | A：乱拳（击退距离 +25%）／B：猴王分身（额外 1 次弱推） |
| 路障 `barricade` | 无敌巨掌 🤚 | **掌风反击**（被攻击时向攻击方向放穿透波） | **太极化劲**（将命中路障的敌弹弹回） | A：千斤坠（路障 HP +120，减速 0.4→0.55）／B：反弹强化（弹回伤害 ×2） |
| 拒马 `stakes` | OTTO♿ | **盒子**（部署子体，复制相邻设施最弱效果 50%） | **大象踩踏**（周期范围伤害 + 0.4s 硬直） | A：复读（复制 70%）／B：象群（踩踏半径 +40%） |
| 维修站 `repair_station` | 工程组 | **快速维修**（维修量 4→6） | **过载修复**（维修 ×2，之后 8s 内该设施攻速 −20%） | A：应急（维修同时给 1 次护盾）／B：散热（消除过热惩罚） |
| 供能站 `energy_station` | 工程组 | **稳定供能**（能量 0.15→0.20） | **护盾供能**（范围内设施受伤 −20%） | A：超频（能量上限再 +0.05）／B：共振（供能同时 +1 格范围） |

**与现有实现的兼容**：`reach`/`focus` 两个全局分支保留为「树的第 1 点」的**通用层**（20 星砂、不可逆）——即第一点仍走现有 `branches`，第二、三点走新表；这样 `Expansion.Attributes()` 只需追加读取新表，旧测试与旧存档不受影响。

## 1.4 点数与节奏（对齐已实现的波次与奖励口径）

| 来源 | 数量 | 代码挂钩 |
| --- | --- | --- |
| 每次升级 | 1 RP | `Progression.Threshold` = 20+10×(等级−1)（不变） |

## 2.5 生成与迁移顺序

**生成管线（种子可复现）**：地区模板 → 房间图（沿用 `RoomGraph`）→ 走廊（MST + 1~2 条环路）→ 地形填充（噪声 + 约束）→ 地标/掩体/危险区 → 可达性校验 → 种子存档。

**硬约束**：① 核心与三入口可达；② 任一掩体破坏后仍连通（v0.3 D02 要求）；③ 危险地形不压核心 3 格；④ 建造槽不被地形占满；⑤ 同种子同布局；⑥ 门的开闭必须同时失效网格、路径、LOS 三种缓存。

**迁移顺序（先易后难，每步都能单独验收）**：

| 步 | 内容 | 为什么这个顺序 |
| --- | --- | --- |
| T1 | 方格地形（沼泽）接入 A 区 | 复用现有方格实现，先验证"地形进战斗"的管线 |
| T2 | 环形几何（沙漠）接 C 区 | 环形只改距离/邻接/弧长换算，风险中等 |
| T3 | 六边几何（极光）接 B 区 | 六边要动 LOS 与门宽校验，风险最高放最后 |
| T4 | 三地区同时挂载 + 大远征路线重标定 | 与 E5 时限/预算一起测 |

## 2.6 与已实现 E1–E5 的联合标定（必做）

| 项 | 现状 | 地形引入后 |
| --- | --- | --- |
| 探索窗口 | 基础 15s + 奖励 ≤15s，上限 30s | 泥沼/雾会拖慢探索 → 需要复核"30 秒能不能走完近侧房" |
| 每房核心预算 | 每波每房 100（10%） | 地形让某房更好守 → 可能出现"只守一间"的最优解，需要 `challenge_target` 与奖励结构压制 |
| 远征总时限 | 120s（原型） | 泥沼/沙暴期会顶到上限 → 需实测或按地形动态给时限 |
| 星砂 | 上限 120，仅首清/远征 | 遗迹墙与地形产出必须并入上限，否则经济崩 |
| 设施上限 | 存活 ≤12，槽位 10 | 地形强/弱的槽位差异会放大槽位价值 → 槽位分配要一起调 |
