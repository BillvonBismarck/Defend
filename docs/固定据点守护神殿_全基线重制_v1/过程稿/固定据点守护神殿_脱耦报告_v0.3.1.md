## 2 依赖审计（脱耦前）

对 30 个 `defense/*.lua` 全量统计 require，只有 **2 个文件**触碰 legacy 代码：

| 文件 | legacy 依赖 |
| --- | --- |
| `defense/LegacyFX.lua` | `fx.Particle`、`fx.GameAudio`、`ui.DamageNumber`、`fx.ScreenShake` |
| `defense/Runtime.lua` | `ui.DamageNumber`（仅为设置字体 ID） |

其余 28 个模块只 require `defense.*` 与平台库（`urhox-libs/*`、`cjson`）。另发现 `Particle` 间接依赖
`fx.Glow`、`utils.FPSMonitor`、`utils.PerfQuality`，`FPSMonitor` 的调试渲染里还隐式 require 了 `ui.HUD`。

## 3 脱耦实现（已产出）

包位置：Gitee 分支 **`defense-standalone`** → `standalone/`（`scripts/main.lua` + `scripts/defense/**`）。

1. **内联 FX 层**：新增 `defense/fx/` 7 个文件（`Audio`、`Shake`、`DamageNumber`、`Particle`、`Glow`、`FPSMonitor`、`PerfQuality`），
   均从 legacy 精确内联，只改 require 路径；`FPSMonitor` 去掉 `ui.HUD` 依赖，改为宿主注入 `fontId`。
2. **`LegacyFX.lua` → `FX.lua`**：对外 API 与行为不变（`Init/Update/Events/Render/Stop/SetVolume/SetReducedEffects/GetShakeOffset`、`corePortal/coreEventId/coreAlert`）。
3. **引用改写**：`Board`、`View`、`Runtime` 与两套测试（`EmergenceTests`、`CompletionTests`）的 require 与桩表指向 `defense.FX` / `defense.fx.*`。
4. **独立入口**：`main.lua` 只启动 `defense.Runtime`，不再加载 `network.Server`。

结果：包内 require 只剩 `defense.*`、`defense.fx.*`、`urhox-libs/UI`、`urhox-libs/UI/Core/Theme`、`cjson`。

## 5 落地路径与回滚记录

**发现**：Maker 项目的脚本 API 只有 `GET /api/v1/scripts/list`、`GET /scripts/content`、`POST /scripts/write`，
其中 **write 只覆盖已存在的文件**，无法新建文件（返回 `File xxx not exists`）。

因此：

1. 曾尝试把脱耦包直接写入 Maker 项目：30 个已存在文件写入成功，**8 个新文件创建失败**；
2. 已按事前备份 **逐字节回滚 82/82 个文件**，并抽检 `Runtime.lua`、`LegacyFX.lua`、`Board.lua`、`main.lua`、`Tests.lua` 全部与备份一致 → **项目当前状态与修改前完全相同、可用**；
3. 在项目内落地的剩余动作（需能新建文件的一方执行）：
   - 新建 `defense/FX.lua` 与 `defense/fx/{Audio,Shake,DamageNumber,Particle,Glow,FPSMonitor,PerfQuality}.lua`（内容见仓库分支）；
   - 把 `Board.lua`、`View.lua`、`Runtime.lua`、`EmergenceTests.lua`、`CompletionTests.lua` 的 `defense.LegacyFX` 改为 `defense.FX`；
   - `Runtime.lua` 的 `ui.DamageNumber` 改为 `defense.fx.DamageNumber`；
   - 两套测试里的桩名改为 `defense.fx.*`；
   - 复核通过后再删除 `defense/LegacyFX.lua`，并逐步移除 `battle/`、`meta/`、`ui/`、`fx/`、`social/` 等 legacy 目录。

**回滚方法**：本次改动的原始快照保存在 `standalone/README.md` 说明的备份目录（本机 `/tmp/es_maker`），
若需再次回滚，用同一 API 覆盖即可。
