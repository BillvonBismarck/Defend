# 单机简接联机服务端

> UI 无污染，client 结合 server  
> 项目：Emoji幸存者 · 更新：2026-09-16

---

## 一句话 prompt

把现有 **NanoVG 单机玩法原样保留**（不重写 HUD / 标题 / 战斗 UI），只加一层 **最小联机骨架**：`main.lua` 按 `IsServerMode()` 分流；服务端 headless 只承载 **IAP 发货 + 余额**（`serverCloud`）；客户端玩法仍在 `game.client_main`，用 `clientCloud` 管排行榜 / 成就 / 养成；大厅启动即 1 人匹配，超时用 `GameMode.offline` 降级本地玩；**禁止**把战斗做成场景复制，**禁止**用 `IsNetworkMode()` 当离线判断，**禁止**把排行榜/成就改成服务端写入。

可直接复制给后续 agent：

```
按 docs/单机简接联机服务端.md 做单机简接联机：UI 无污染（NanoVG 玩法/HUD 不换成 urhox-libs/UI）；client 结合 server（同一入口分流，clientCloud 管自己的分和存档，serverCloud 只管发货和余额）。大厅 1 人秒开，超时离线；IAP 挂在 Server.onDeliver。不要做多人同场，不要把排行榜/成就搬到服务端。
```

---

## 这句话在约束什么

| 词 | 含义 | 落地 |
|---|---|---|
| **单机简接** | 不为联机而重做玩法，只接一条「能进权威服」的管道 | `player_number: 1` + `immediately_start` |
| **联机服务端** | 有 headless 服，但服不跑战斗 | `network/Server.lua` 只 IAP |
| **UI 无污染** | 玩法 UI 继续 NanoVG；大厅是另一套生命周期，进游戏后拆掉 | 标题/战斗/商店仍 `nvg*`；仅 `lobby_runtime.lua` 用 `urhox-libs/UI` |
| **client 结合 server** | 同一 `main.lua` 分流；两套云各管各的，用远程事件把服的结果刷回客户端 | 见下文「两套云」 |

## 架构（client 结合 server）

```
scripts/main.lua                    ← 唯一入口
 ├─ IsServerMode()  → network.Server.Start()   headless，提前 return，不加载渲染
 └─ else            → game.client_main         完整单机玩法 + 可选网络层

大厅 scripts/lobby_runtime.lua      ← 仅联机启动路径
 ├─ StartMatch（1 人即可开局）
 ├─ 成功 → 引擎连服、切游戏脚本（代码零参与切场景）
 └─ 5s 超时 / StartMatch 异常 → GameMode.SetOffline(true) → ClientMain.Start{offline=true}
```

```json
"multiplayer": {
  "enabled": true,
  "max_players": 2,
  "lobby_runtime": "scripts/lobby_runtime.lua",
  "match_info": {
    "desc_name": "free_match",
    "immediately_start": true,
    "player_number": 1
  }
}
```

**结合方式**：客户端算战斗、画 UI、写自己的云存档；服务端不复制场景、不模拟敌人。两边只通过 **远程事件 + 云变量** 交换「钻石余额」这一类必须权威的数据。

| 端 | 文件 | 职责 |
|---|---|---|
| 入口 | `scripts/main.lua` | 分流；服务端禁止 require 客户端 UI |
| 协议 | `scripts/network/Shared.lua` | 事件名、`gems` key，两端同一份 |
| 服 | `scripts/network/Server.lua` | `Shop.onDeliver`、查余额、就绪 |
| 客网 | `scripts/network/Client.lua` | 上报 ready、拉余额、收 `BALANCE_*` |
| 玩法 | `scripts/game/client_main.lua` | 原单机逻辑；`HandleXxx` 必须文件级全局 |
| 模式 | `scripts/GameMode.lua` | **唯一**离线标志 |
| 大厅 | `scripts/lobby_runtime.lua` | 匹配 / 超时降级；`stop` 只退订自己的事件 |

服务端脚本 `.meta` 标 `"c_or_s": "s"`，不要打进客户端包。

## 两套云：职责必须分开

这是本方案最容易接错的一点。**不是「开了联机就把所有云操作搬到 serverCloud」。**

| | `clientCloud` | `serverCloud` |
|---|---|---|
| 跑在哪 | 客户端（UrhoXRuntime） | 服务端（UrhoXServer） |
| 能改谁 | **只能改当前登录玩家自己** | 任意 `userId` |
| 事务 / 订单 | 无订单幂等 | `BatchCommit({ orderId })` 原子发货 |
| 本项目用途 | 排行榜、成就、养成、昵称同步 | **仅**钻石发货与余额 |
| 对应文件 | `client_main` 排行榜、`Achievement`、`SaveData` | `network/Server.lua` |

### 必须用 serverCloud 的

- 内购发货：`MoneyAdd(userId, "gems", n)`，带平台 `orderId`，重复回调不多次到账
- 离线补单：`ctx.conn == nil` 也要入账，玩家下次连上从云端读到
- 给「这个订单对应的那个玩家」加货币——客户端做不到安全地改别人的钱

### 必须留在 clientCloud 的（不要「顺便」改成服务端）

- **排行榜** `best_wave` / `best_kills`：玩家上报自己的最高分，`GetRankList` 原生成榜；客户端改不了别人的分
- **成就** 位掩码：本地 ∪ 云端，写回自己的 iscores
- **养成存档** 金币 / 遗物 / 图腾 / 符文 / 皮肤：按现有合并策略同步

这些是「自己的云存档」，不是「给别人发货」。过早搬到 `serverCloud` = 把整局战斗做成服务端权威，和这次「简接」目标相反。

### 什么时候才值得把排行榜/成就搬到服

1. 要防客户端把 `best_wave` 写成 99999  
2. 成就和付费绑定（买礼包才解锁）  
3. 需要给别人写分（公会榜、赛季由服结算）  

当前没有这三条，**禁止**为了「已经联机了」去改。

### 数据合并（clientCloud，联网拉档时）

| 字段 | 策略 | 原因 |
|---|---|---|
| 金币 / 最高波次 / 遗物等级 | 取大 | 多端游玩取进度高的 |
| 图腾 / 装备 / 符文 / 皮肤 | **本地权威** | 合成会变少，云端旧数据回写会「丢图腾」 |

## UI 无污染

原则：**玩法界面零迁移**；大厅是进游戏前的另一段 Runtime，进游戏后由引擎回收。

| 层 | 技术 | 为什么不算污染 |
|---|---|---|
| 标题 / 战斗 / HUD / 充值弹层 | 原 NanoVG | 不引入 Yoga 控件树，不改绘制坐标系 |
| 自定义大厅等待页 | `urhox-libs/UI` 挂在 `ctx.root` | 只在匹配阶段存在；`stop` 后 root 由引擎拆掉 |
| 充值 | `ui/RechargeShop.lua` 仍是 `nvg*` 弹层 | 标题页加一个按钮，不换整页 UI 框架 |

硬约束：

- 不要把 `RenderTitle` / `HUD` 改成 `UI.Panel`
- 大厅 `SubscribeToEvent("Update")` 必须在 `stop` 里 `UnsubscribeFromEvent`，**不要** `UnsubscribeFromAllEvents`（会误伤即将启动的游戏）
- 游戏侧 `ClientMain.Stop()` 才 `UnsubscribeFromAllEvents` + `nvgDelete`，保证可反复进出
- `HandleUpdate` / `HandleNanoVGRender` / 触摸系列保持 **文件级 `function HandleXxx`**，字符串订阅靠文件作用域

## 离线降级（和两套云直接相关）

`IsNetworkMode()` 在大厅启动后就是 true，超时进本地也不会变。  
**离线只认 `GameMode.offline`。**

短路点：

| 能力 | 做法 |
|---|---|
| 充值 | `RechargeShop`：离线不 `require Shop`，提示需联网 |
| 排行榜 | `LoadLeaderboard` / `UploadCloudScores` / `LoadOwnCloudBestWave` 直接 return |
| 云存档 | `SaveData.getClientCloud()` 离线返回 nil，一处收口 |
| 成就云同步 | `Achievement.SyncFromCloud` / `SyncToCloud` 离线 return |

标题页离线时显示「🔄 重试联机」：停本地游戏 → 再 `StartMatch`。

## 远程事件（client 结合 server 的唯一热路径）

`network/Shared.lua`：

| 事件 | 方向 | 作用 |
|---|---|---|
| `IAPClientReady` | C→S | 连上后登记，服推一次余额 |
| `IAPRequestBalance` | C→S | 进商店 / 进游戏再拉 |
| `IAPBalanceSync` | S→C | `{ gems: int }` |
| `IAPBalanceDirty` | S→C | 发货成功，客户端再请求一次 |

接收端必须 `RegisterRemoteEvent`。处理函数必须定义在**订阅它的那个脚本文件**里（`Client.lua` / `Server.lua`），不要写进 `client_main`。

发货成功链路：

```
Shop.purchase → 支付弹窗（回调只表示弹窗已拉起）
  → 平台 → Server.Shop.onDeliver
  → serverCloud.BatchCommit + orderId（幂等）
  → BALANCE_DIRTY → 客户端 RequestBalance → 刷新「余额：gems N」
```

---

## 明确不做

- 场景复制、pawn 池、`PlayerSessions`、战斗权威服
- 用 `IsNetworkMode()` 判断离线
- 排行榜 / 成就 / 养成改 `serverCloud`
- 把 NanoVG HUD 换成 urhox-libs/UI
- 服务端 `require` 任何渲染 / HUD / 商店 UI 模块

## 验收

1. 联机构建：`multiplayer.enabled=true`，LSP 0 error  
2. 预览：大厅出现「正在匹配对局…」；成功则进原标题页；5s 失败则离线可玩  
3. 标题页 NanoVG 未换框架；有「💎 充值」  
4. 联网无商品时商店文案为「内购未开通或暂无商品」（不是崩溃）  
5. 离线：充值提示需联网；排行榜「联网不可用」；本地存档仍读写  
6. IAP 白名单开通后：支付 → `onDeliver` → 余额 toast「余额已更新」
