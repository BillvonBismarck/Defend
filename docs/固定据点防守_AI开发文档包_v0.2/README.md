# 固定据点防守 AI 开发文档包 v0.2

合并主玩法策划案 V0.1 与涌现式底层设计补充案 V0.1，形成可供游戏开发 Agent 分模块读取、实现和验收的 Markdown 资料。当前交付只整理文档，没有读取 Emoji 幸存者项目代码，也没有开展游戏开发。

## 开始使用

1. 将整个目录放入后续开发仓库的文档目录，保留相对路径和 assets。若仓库已有 AGENTS.md，将本包入口合并进去，保留仓库原有规则。
2. 开发 Agent 先读 [Agent 工作入口](AGENTS.md)、[范围与设计权威](00_范围与设计权威.md) 和 [v0.2 更新记录](93_v0.2更新记录.md)。
3. 首个开发任务应是 [技术复用核验](10_技术复用核验.md)。拿到实际仓库、平台和引擎证据后，再选择 [阶段任务](11_开发阶段与任务.md)。
4. 每次实现一个任务，按其引用的规则及 [验收用例](12_验收用例.md) 提交证据与交接记录。

## 给开发 Agent 的启动请求

```text
读取本目录 AGENTS.md 和 00_范围与设计权威.md。
当前任务仅执行 T00 技术复用核验；先检查实际游戏仓库的指导文件和运行方式。
核验统一空间、伤害/死亡、暂停时钟、事件队列、身份与性能能否支持补充方案。
将源码证据、可复用模块、缺口、平台限制和推荐的阶段 A 范围写成核验报告。
对 P 原型建议保持候选状态，对 E 工程建议说明采用理由，对 Q 未决设计列出依赖。
完成核验后报告下一步可执行任务及其验收方法。
```

目录中的规则标记与优先级见 00。原文中的“正式交付 Word PNG SVG PDF”是原策划案的历史交付要求，本次交付格式按用户当前请求使用 Markdown，附原图用于地图与循环核对。
