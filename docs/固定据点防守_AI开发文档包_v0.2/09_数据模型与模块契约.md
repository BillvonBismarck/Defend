# 数据模型与模块契约

来源：[原文第九节配置建议](90_原文转录.md#s09)。主案与补充案给出的字段和队列顺序为 P 方案接口；主案原字段、E 补充分层与新增补充案协议在下文分别标明。未归为来源协议的类型、事件和职责划分是 E 工程建议，便于 AI 协作交接，可按实际项目改名。平台、引擎、保存介质未指定。

## 原文字段与建议类型

| 层次 | 字段 | 建议语义 |
| --- | --- | --- |
| 关卡 | core_position / core_max_hp | 二维逻辑格位置 / 正数耐久上限 |
| 关卡 | player_spawn / portal_positions | 玩家坐标 / W E S 到坐标的映射 |
| 关卡 | build_slots / room_unlocks | 四槽位清单 / 三条一级到二级依赖 |
| 波次 | wave_id / active_portals | 正整数 / 合法入口列表 |
| 波次 | spawn_batches / portal_offsets | 显式生成批次 / 入口错峰时间，单位秒 |
| 波次 | elite_count / boss_type / reward | 精英数量 / 可空类型 / 清波奖励 |
| 波次 | alive_soft_limit | 候选 80；计数范围在 Q05 中确定 |
| 运行态 | run_state / wave_alive_count | 当前状态 / 当前波存活进攻怪计数 |
| 运行态 | core_hp / repair_uses | 核心当前耐久 / 本局修复次数 |
| 运行态 | room_state / claimed_rewards | 每房状态 / 已领奖标识集合 |
| 运行态 | story_seen | 演出记录；作用域待 Q10 |

字段出现于策划案不表示原项目有同名实现。实际代码复用后记录对应路径与类型。

## E 建议补充字段

| 对象 | 建议字段 | 用途 |
| --- | --- | --- |
| 关卡配置 | map_size、walkable_regions、obstacles、coordinate_scale | 保存灰盒边界、柱体和单位转换 |
| 本局运行 | run_id、current_wave_id、player_hp、currency、level、experience、skill_build | 明确本局身份与资源状态 |
| 波次运行 | queue_cursor、pending_batches、generation_complete、alive_entity_ids | 区分未生成、已生成和已死亡，便于校验计数 |
| 时间 | preparation_remaining、warning_elapsed、pause_reasons、resume_state | 可暂停计时、覆盖层恢复与预警补足 |
| 敌人 | entity_id、role、wave_id、room_id、origin_portal | 进攻怪/守军隔离和卡怪回迁 |
| 设施 | slot_id、type、upgrade_count、hp、total_spend | 槽位、升级次数与累计成本 |
| 据点 | unlocked、guard_states、reward_claimed、recall_progress | 解锁、守军伤害持久与回城 |
| 局外记录 | settled_stage_records、unlocked_chapters | 失败保留已结算奖励与解锁 |

持久记录和本局对象分开保存。是否支持中途存档恢复是 Q14，不因出现运行态字段就增加自动续局功能。

## E 模块职责和边界

| 模块 | 负责内容 | 接口边界 |
| --- | --- | --- |
| RunController | 状态、时钟、暂停、胜负、重试 | 模拟权威；UI 请求不能直接改核心状态 |
| WaveDirector | 批次、入口、延期和生成完成 | 队列完成、存活清空及待结算有害反应分别报告 |
| Combat | 命中、目标选择、技能、伤害和死亡 | 核心、角色、设施区分；实体死亡一次 |
| Progression | 经验、合法候选、溢出升级 | 通过暂停接口开关选择覆盖层 |
| Economy | 资源来源、交易、修复次数、返款 | 一次请求一笔合法事务 |
| MapAndRooms | 通行、守军、解锁、领取、回城 | 守军生命周期与波次计数隔离 |
| Presentation | HUD、小地图、声音、剧情 | 读取快照，发请求，显示结果 |
| MetaRecords | 阶段已结算记录、章节解锁 | 新局重置不抹除已结算局外记录 |

## E 事件契约

建议共同字段 run_id、event_id、模拟时间；这些是接口建议，不要求某一事件总线库。

| 事件或请求 | 最小负载 | 一致性要求 |
| --- | --- | --- |
| SpawnRequest / EnemySpawned | wave_id、入口、实体 ID、类型 | 延期请求不算已生成；Boss 召唤归当前波 |
| EnemyDied | 实体 ID、wave_id 或 room_id | 重复死亡不重复减计数或奖励 |
| WaveCleared | wave_id | 队列完成、存活进攻怪为 0、本波待结算有害反应已处理才发 |
| CoreDamaged | 当前耐久、伤害来源方向 | 警报及时显示，失败检查优先 |
| ExperienceGranted / UpgradeChosen | 数额 / 候选 ID | 阈值与合法候选可追踪，恢复原状态 |
| LogisticsRequested / TransactionResolved | 操作、槽位、价格、结果原因 | 模拟层重验状态、金额、次数与上限 |
| RoomCleared / RoomRewardClaimed | room_id | 一级清空解锁二级，领奖每局一次 |
| StoryRequested / StoryCompleted | 节点 ID、播放方式 | 副作用一次，跳过与回看不重复生成 |
| RunEnded | 结果、波次、结算记录 | 结局只确定一次，结束后停止战斗副作用 |

幂等键可建议用 run_id + wave_id + 奖励类型，或 run_id + room_id；具体机制按项目选择。复现测试可使用固定随机种子，生产随机算法不由本包指定。

验收关联：V01 至 V19。模型约定的变更同步更新任务交接与接口调用方，原型初值仍以各玩法模块中的来源表为准。

## 补充案 P 实体 效果与因果协议

来源：[补充案第十节](92_补充案原文转录.md#e10)。以下字段不代表 Maker 已有 API。

| 协议 | 补充案最小字段与语义 |
| --- | --- |
| 实体 | entity_id、team、position、collision、hp、weight、anchored、可受状态、death_reaction、wave_id / room_id，死亡唯一已提交标记 |
| 效果 | 目标过滤、距离、遮挡政策、伤害、位移、状态来源与期限、触发条件；共用空间/状态接口 |
| 因果事件 | event_id、parent_event_id、root_action_id、source/target_id、计划时间、实际位置、前后状态、命中或失败原因 |
| 排序 | 计划模拟时间 + 稳定序号，死亡反应排队，不递归调用下一次死亡 |
| 身份 | 进攻怪与守军隔离；死亡、掉落、奖励、wave_alive_count 分别去重 |

root_action_id 从原始动作沿 parent_event_id 贯穿连锁，用于追踪与摘要合并，不按链深再发奖。同一个根动作可能杀死多个实体，因此不能仅用 root_action_id 去重所有奖励。每个死亡实体各有一次结算，各副作用域再去重，属于 E 去重键建议。

## 补充案 P 因果提交顺序

合法性过滤 → 空间/遮挡查询 → 提交位移与状态 → 提交伤害 → 提交死亡 → 安排反应及一次性结算 → 更新波次/据点 → 同时间槽胜负裁决 → 真实反馈。

同一效果包先位移后伤害，死亡位置使用提交后坐标；不同效果按稳定序号处理。爆炸延时事件锁定死亡点，到期查当前存活目标、距离和遮挡。后续死亡产生队列事件，不递归即时引爆。当前首轮主动击退不附带伤害，混合效果包属于接口测试，不擅自增加玩家技能。

暂停冻结模拟时钟、队列以及状态时限；恢复保持顺序，无补发或漏发。失败优先，清波门槛读取 [01 R02](01_主循环与状态机.md#r02-胜负和清波)。首版仅一次性死亡反应和有期限状态，不开放同源攻击重触发或连锁重置冷却。

## E 建议新增运行字段与模块

| 建议项 | 用途 |
| --- | --- |
| scheduled_events、next_stable_sequence | 保存有序待处理事件，计划时间均为模拟时间 |
| pending_harmful_reactions、reaction_scope | 计算本波危险结算门槛，归属范围由 Q19 明确，不与活怪计数混用 |
| death_committed、reaction_scheduled、reaction_committed | 防止同一实体的死亡或反应重放 |
| side_effect_ledger | 按实体和副作用类型去重死亡/掉落/奖励/计数 |
| active_statuses | 来源、强度、剩余时限，支持同源刷新/异源计时 |
| opportunity_tags、actual_context、prompt_state | 记录机会条件与提示使用；不等同于玩家理解 |
| anonymous_playtest_id、session_index | 本地匿名试玩记录和第几局，不采真实账号 |

建议统一 EffectResolver 与 CausalQueue 为战斗子模块，交给 RunController 的时钟驱动；WaveDirector 查询待结算危险门槛。Presentation 读取已提交结果，生成摘要或演出标记，没有修改伤害或补发奖励权限。playtest 意图与理解从观察/访谈附证，不能从 root_action_id 自动推断。

新局隔离 run_id 和旧队列，取消旧局尚未提交副作用；已提交局外记录按原案保留。事件追踪、重试清理与存档续局分开，Q14 的中途保存仍未新增授权。

性能可用空间索引、碰撞查询复用与表现对象复用；只能优化表现或后续批次预算，不能静默截断链深或命中对象。压测与身份校验见 V24–V27。
