# 范围与设计权威

来源：[原文概览](90_原文转录.md#s00)、[原文第九节](90_原文转录.md#s09)、[原文第十节](90_原文转录.md#s10)。补充来源：[补充案概览](92_补充案原文转录.md#e00)、[衔接要求](92_补充案原文转录.md#e12)。本文件规定后续 Agent 如何解释其余文档。

## 规则状态

| 标记 | 含义 | 开发时的处理 |
| --- | --- | --- |
| C | 原文列为已确认的边界 | 作为设计约束；修改需有新的用户决策 |
| P | 原文的制作假设、建议或规则候选 | 可以用于经授权的原型验证，保留参数与来源，不能宣称最终确认 |
| D | 从原文明确规则直接推导的说明 | 核对前提，不能用它扩张玩法范围 |
| E | 此次拆解补充的工程组织建议 | Agent 可结合实际项目采用或替换；记录选择，不冒充原文要求 |
| Q | 原文空缺、冲突或需要实测的问题 | 关联到 13 中的决策项；设计影响未定时保留待确认 |

模块正文默认属于 P 原型方案，只有明确标出的 C 才属于已确认边界。验收用例检验候选方案的实现一致性，不会把候选方案升级成用户确认。原文原型数值是配置初值，不能作为最终平衡承诺。

## 解释与变更顺序

新的直接用户决策优先于旧策划案。无新决策时，已确认边界优先于候选设计；原文保留候选设计的权威来源，E 补充建议服从设计来源。正文与图示出现歧义时，将它登记为 Q，引用两方证据并等待设计决策，不能悄悄修改一方。

当前文档包是开发输入转换，不是新一轮功能确认。要改变波数、平台、技能、地图或剧情，先在 [决策记录](13_待确认事项与决策记录.md) 留下理由、状态及受影响文件；当前未决项不会阻止独立的源码核验工作。

## 统一术语

| 术语 | 定义 |
| --- | --- |
| 核心 | 防守对象，独立耐久、固定坐标 |
| 进攻怪 | 由当前波生成、对守核形成压力的敌人，纳入该波存活计数 |
| 外圈守军 | 据点房内敌人，不纳入波次清空判定 |
| 波次入口 | W、E、S，清据点不会关闭它们 |
| 据点 | A1/A2、B1/B2、C1/C2，房间状态与奖励独立于波次 |
| 战备 | 可探索与后勤交易的 15 秒游戏时间窗口，末 8 秒可与方向预警重叠 |
| 清波 | 生成队列完成、当前波进攻怪全部清空且本波待结算有害反应已处理；不是到时或只杀 Boss |
| 局内状态 | 本次运行的等级、资金、设施、据点与战斗状态 |
| 局外记录 | 已结算阶段奖励与章节解锁，失败保留 |

核心、据点、统领均为功能名，保持叙事占位。原图是原创样板示意，不是参考游戏地图复刻；逻辑格不等于素材像素。

## 补充案的权威与范围

补充案保留主案核心 (32,21)、W/E/S 入口、四建造点、20 波基线、15 秒战备、8 秒预警以及已有建造/修复价格。它明确新增持续涌现目标 C05，但同时说明具体击退、爆炸怪、减速、教学与指标仍需评审和原项目核验。保留基线意味着本次整合不改原数值，不意味着所有旧候选已被最终确认。

本次授权是合并开发文档；两份来源 `.doc` 和原 v0.1 包均保留。补充案对交互方案的明确说明补足旧包缺口，例如候选减速采用最强值而非无限相乘；清波门槛新增有害反应等待。若新旧解释不同，按 [93 更新记录](93_v0.2更新记录.md)中列出的局部补充处理，其余保留主案。

首原型只建议验证空间控制与时间/资源控制两组关系，暂不扩大成六元素体系、复杂化学模拟、新地图或额外付费成长。后续新套装、重装敌人与章节几何另行评审。P 来源方案的接口需求与 E 拆解建议在 [09](09_数据模型与模块契约.md)分别列明。
