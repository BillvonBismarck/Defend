# 验收与证据

以下均是未来实施用例，本次文档制作未运行游戏测试。PASS/FAIL 表示已实际执行的结果；NOT_RUN 表示未执行；UNDETERMINED 表示执行后证据不足或运行条件异常。

## 规则用例

| ID | 输入与操作 | 预期结果 |
| --- | --- | --- |
| B01 | 同一塔、等级、技能分别安装基础/两个模块，给单体与密集目标 | 配置与实际命中/穿透/范围/目标策略一致；卡面有效数值匹配，不只变化名称 |
| B02 | 三类塔同时减速同敌人，叠加角色冷凝；普通/Boss分别测 | 同源刷新、异源时限、最强及上限/Boss半效正确；新模块不另乘减速 |
| B03 | 首次领奖、重复claim、重复选择、库存不足三项、库存全满、重试 | 金币经验及模块机会各一次；候选合法且无重复；重试不继承本局库存 |
| B04 | 战斗期、更换费不足、非法模块/槽、重复request_id | 非法操作无资金/塔变化；成功请求重放返回原结果；更换保留生命、冷却与等级 |
| B05 | 建造/升级/付服务费后拆除；受损拆除；达到存活上限后摧毁重建 | 返款仅按可返基础成本，损坏遵守旧规则；无服务费套利；上限正确释放 |
| M01 | 原地图样板及扩展布局，逐路径带真实半径移动 | 必需房间、核心、后勤可达，穿墙为零；配置连接边与真实路径对应 |
| M02 | 在扩展地图按至少三种探索顺序，含深层点和捷径 | 解锁依赖无环；收益/行程有差异；捷径真实缩短至少一条合法路径 |
| M03 | 未清、未解锁房间位于远征线上，考验开门；玩家随后进入 | 物理门实际开放，缓存失效；远征可过；玩家进入能激活守军；未清不可建造，未自动领奖 |
| M04 | 修改地图宽高/原点，桌面及竖屏查看雷达和列表 | 地图比例读取配置，标记不漂移；核心警报、操作、模块和房间信息可访问 |
| M05 | 满配置房间/设施/进攻怪与连锁，关闭远处表现 | 逻辑不漏步、事件不丢；记录CPU/帧时/路径查询及缓存变化，表现裁剪不改伤害 |
| R01 | 已清未领、已领、未清各尝试外围建造，考验多次经过 | 权限遵守清空条件；原状态保留；重复经过无原房间金币/经验/模块奖励 |
| R02 | 考验外/内观察外围塔，受损/摧毁/修复重建后再次考验 | 激活策略、范围、生命及冷却如实；敌人过境不刷守军，设施寿命独立于房间奖励 |
| R03 | 普通队列耗尽但特殊单位尚未生成/存活/转场 | generation_complete与AliveCount反映特殊单位，无提前结算；软上限延期不丢队列 |
| R04 | 比较未探索、仅清空、已布防的同一路线 | 三种状态均能运行；布防实际改变承伤/终局生命，复盘按实际来源记录 |
| X01 | 固定seed遍历样板及扩展路线，检查每个物理站点 | 顺序与预告一致，每个challenge_target到达；entity_id不变，无跨房间传送 |
| X02 | HP充分且剩余预算10，单次伤害30；新夹具同槽8/8；另测极高致死伤害 | 单次实际10，同槽实际8/2；巡行至少1HP；转场后后续伤害为0 |
| X03 | 角色、塔、溅射、延时爆炸同时命中，含墙遮挡/跨站飞行弹 | 全部走公共限伤；遮挡仍有效；以提交时站点判定，无私有扣血入口 |
| X04 | 到预算/到计时/无玩家三分支；离房再进、击退到旧房间 | 各分支可推进；已消费预算不重置；站点索引不回退，无重复奖励 |
| X05 | 手动/升级/模块/失焦暂停；恢复；退出及重试 | 时钟、交战计时、伤害预算和队列冻结；恢复无补发；新局无旧主敌/预算/反应 |
| X06 | 低输出完成巡行，高输出完成巡行，随后攻击终局 | 剩余HP不同且继承；护甲提示正确；终局可击杀一次，沿途预算耗尽不假死 |
| X07 | 临时合法阻挡/门变化导致卡路及持续不可达 | 先重寻当前路点；不回出生入口；最终异常记录技术错误，不发胜利或删怪 |
| C01 | 主敌携带current_room_id并跨站，重复Spawn/Death操作 | 仍属于波次进攻实体；不误设守军room_id；死亡/掉落/活怪结算唯一 |
| C02 | 最后敌人死但有延时危险；同槽核心死亡；终局演出/回看 | 危险结算完才清波；失败优先；故事暂停/回看不再生敌人或再发奖励 |
| C03 | legacy_v02原回归；样板胜利；扩展场景胜败与重试 | 原20行、1176及波次休息公式保留；样板不解锁旧章节；场景/记录不串局 |

X02 同槽夹具保持交战计时未耗尽、HP足够且仍在合法房间，确保断言预算裁切而非其他免伤。到时转场或HP保底的分支独立测量。

## 体验与运行用例

| ID | 操作与证据 | 判断标准 |
| --- | --- | --- |
| E01 | 至少两种构筑、相同资源条件、不同探索顺序，真实移动与战斗 | 能展示不同拦截/回核决定及收益代价；不得用强制击杀证明平衡 |
| E02 | 玩家探索→选模块→外围建造→考验；再做放弃探索/集中守核对照 | 能说明探索投资何时值得、何时该放弃；设施对角色分工有可见影响 |
| E03 | 初次观看预告与限伤，之后无配方提示处理新房间情境 | 玩家可解释护甲、站点预算和终局继承；记录原话与动作，日志不替代理解 |
| E04 | 桌面/竖屏目标环境，全路线、危急核心、模块面板、减少特效、音效及满负载 | 当前截图/日志可追溯；关键信息不遮挡；设备和性能实测完整，未测试设备明确列出 |

至少记录到达/退出、核心损失、资金支出、玩家/塔输出、每站预算、路径长度、战备奖励与实际探索耗时。小样本仅用于诊断，不宣称留存率或长期平衡。

## 执行方法与证据边界

旧 CPU 回归入口为 `python validation/defense/run_audit.py`，它会写 audit-rule-report.json；未来开发时运行前保存旧证据，按实际环境确认 Python/lupa 是否可用。新用例可通过防守测试注册入口或独立纯 Lua 夹具接入，并纳入实际调用的 runner。

语法/LSP、CPU规则、引擎画面/音效、完整实战、真人理解分别报告。历史 50 PASS/4 NOT_RUN 不是新增系统的验收结果。LSP基线错误与新增错误分别列出，不能通过关诊断获取“通过”。

代码资源编辑后按根政策检查本地 preview；存活才刷新并取证，停止会话保持停止。远程构建只随显式构建/提交请求执行。缺失Runtime不要求本次文档任务安装或启动。
