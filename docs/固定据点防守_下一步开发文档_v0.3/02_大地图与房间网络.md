# 大地图与房间网络

依据 U03。P 解释为同一关卡的可探索空间，固定核心继续适用。跨章节世界地图、随机地图生成不是本轮默认目标。

## M01 结构与制作尺度

采用“物理通行几何 + 房间连接图”双层表示。连接图服务路线规划、解锁和展示；碰撞、LOS、移动与最终命中仍用同一物理空间。

P 完整原型含 8–12 个探索/防守房间，分成三个外圈区域：每区有近侧收益点和深侧策略点，区域之间至少有两处连接，使玩家可绕行。至少一个清房后开放的玩家捷径连接深层区域与主殿附近。

地图逻辑宽高按布局实际包围盒配置，不预先把倍率当作合格证据。大地图需同时增加房间职责、路线选择和可复用防守节点。各房间配置 reward_kind、guard_profile、defense_slots、challenge_target 等明确职责。

第一步复用 A1/B1/C1 做三房间样板。可先采用“主殿→房间→主殿→下一房间”的真实折返路径验证，之后增加外圈环路；文档不声称现有六房间已经构成环路。

## M02 节点、边与锁

节点含核心区、后勤区、探索房间、连接点；边含起终点、可通行角色类别、开放条件及用于估时的真实路径长度。所有 ID 唯一。解锁条件无循环依赖，所有玩家必达点至少有一条合法路径。

将探索锁与考验路线通行条件分别建模。未探索房间不能使远征永久卡死。P：考验开始前统一打开沿线物理门，发出 GateOpened 事件、刷新地图缓存；该动作不清守军、不领取奖励、不授权未清房间建造。玩家也能通过已打开的物理门，不使用不可见的敌人穿墙权限。

守军仍只在玩家进入可访问房间时激活，远征主敌不触发探索激活。可访问条件是探索解锁或考验已开门；清空/领奖状态保持独立。先检查当前 UpdateRooms 的 room.unlocked 条件并同步迁移，避免“门已开却没有守军”的双状态矛盾。守军与远征主敌同阵营，避免未经设计的新敌我混战。

玩家捷径与远征路线分别配置。主敌按预告的 route_id 走实体路径，不因玩家打开捷径就跳过必经房间。路径重算只绕实际障碍，不改变预告节点顺序。

## M03 时间、回防与地图信息

战备继续读取现有基础时间和快速清波奖励。用实际路径长度、角色有效速度、守军战斗及领奖耗时估算探索行程，并以游玩校准。

UI 标示已知房间、清空/未领/可部署状态、核心与入口、已开放捷径、考验路线及下一站。P 首原型公开地图轮廓和考验路线，不增加战争迷雾。

回防提示基于路径估时及战备剩余时间：路径不通时提示原因；不能只用直线距离保证“来得及”。保留战斗中禁用回城、战备已清据点引导回城及其打断规则。

扩展 Radar 的 64/48 硬编码为 map_size，支持非零地图原点时按配置换算。房间列表采用分区/滚动结构；桌面与竖屏都保持核心警报、升级卡和触屏操作区可见。

## M04 寻路与性能

复用 Map.Path、IsWalkable、Move、LineOfSight；按实体半径验证门宽和拐角。门变化须同时失效网格、路径和 LOS 缓存。

新增设施采用合法固定槽位，不阻塞必经通道。远处表现可降频或裁剪，已激活守军伤害、塔冷却、远征移动和因果事件继续依模拟时钟处理。

完成条件：扩展地图实体可走；环路和捷径真实存在；全部 challenge_target 房间被远征路线覆盖；每条必要路径可用；三种探索顺序有不同成本/收益；画面与性能通过 M01–M05、E01/E04，见 [07](07_验收与证据.md)。
