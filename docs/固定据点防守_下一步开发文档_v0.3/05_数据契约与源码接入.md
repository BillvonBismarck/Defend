# 数据契约与源码接入

本文为 E 接入建议，字段/模块尚未实现。沿用 [v0.2 公共协议](../固定据点防守_AI开发文档包_v0.2/09_数据模型与模块契约.md)，新增字段保持用途独立；规则默认方案见 08。

## D01 配置与运行态

| 层次 | 候选字段 | 约定 |
| --- | --- | --- |
| 场景 | scenario_id、rules_version、map_size、map_origin、total_waves、final_intro_wave、record_namespace | legacy_v02 / reuse_sample / large_map_proto 分开；原模式默认行为保留 |
| 房间定义 | id、region_id、guard_profile、reward_kind、module_reward、defense_slots、challenge_target | 地图、奖励、守军和布防职责显式配置 |
| 房间运行态 | prerequisite_satisfied、challenge_gate_open、accessible | accessible由前两项推导；当前unlocked的通行/激活调用方统一迁移，探索state与领奖不自动改变 |
| 房间图 | nodes、edges、gate_id、unlock_condition、path_length | 拓扑与实际通行几何可互相核对 |
| 槽位定义 | id、x、y、owner_room_id、activation_region_id | 主殿 owner_room_id 可为空；远征计数不读取这些字段 |
| 塔 | module_id、module_revision、build_spend、upgrade_spend、service_spend | 服务支出与可返成本分开，旧 total_spend 迁移保留原结果 |
| 本局库存 | module_inventory、pending_module_choices、room_module_claims | 本局拥有状态；重试清理，不扩展永久存档 |
| 波次 | challenge、special_units、special_count | 普通表及特殊单位分别校验，不能误归普通总数 |
| 远征定义 | route_id、waypoints、stops、engage_duration、room_caps、final_target | 无效路线/预算在生成前拒绝，不静默修复 |
| 远征实体 | behavior、route_id、route_index、stage、stage_elapsed、current_room_id、damage_ledger | current_room_id 仅空间信息；与守军 room_id 分离 |

room_id 继续是“外圈守军归属”；远征主敌保持 room_id=nil 且 wave_id=当前波。未来如统一 identity 字段，必须一并迁移 AliveCount、Spawn、移动房间限制、掉落归属、死亡事件和 UI 调用方。

远征 current_room_id 变化不改变实体身份、掉落或波次归属。新role需配置敌人基础属性、emoji映射及is_boss标签，并同步当前boss角色白名单、重量/减速半效、生成和掉落查询；不能只在导演中增加陌生role。召唤若未来启用，也明确归当前波；本次 P 无额外召唤。

## D02 模块职责

| 当前模块 | 接入点 | 要处理的限制 |
| --- | --- | --- |
| Config.lua | 场景、塔模块、房间图和考验数据 | 单一数据权威，避免 UI/测试另写可编辑表 |
| Run.lua | 场景选择、库存、暂停、计数、终局和快照 | 当前只区分5/20波，终局第20波及章节记录需场景化 |
| Runtime.lua | makeRun、action 路由、场景切换和退出 | 当前未传场景配置；重试需保留 scenario_id 并清旧实例 |
| Economy.lua | 模块事务、外围槽、上限、返款成本 | 所有权限在模拟层验证，重复 request_id 返回原结果 |
| Progression.lua | 角色成长与模块选择的面板协调 | 模块库存选择与角色经验升级分开，暂停源不可互相覆盖 |
| Combat.lua | 塔模块、外围激活、DamageEnemy、stepEnemy、恢复路径 | 限伤接公共伤害入口；行为类型不滥用守军房间锁定 |
| Map.lua | 房间图、门变化、路线校验、回防估时 | 原 PortalPoint/PrepareWave 面向三入口，新增路径保持真实几何 |
| WaveDirector.lua | 特殊单位队列、生成完成、软上限 | BuildQueue Boss白名单及 Validate 原20行断言需兼容场景 |
| Reactions.lua | 延时反应、稳定顺序、去重、关闭 | 新阶段不删除旧有害反应，保持 parent/root 链 |
| View.lua / Board.lua / Radar.lua | 模块详情、分区房间、路线与限伤快照 | Radar 硬编码64/48；GUI读快照，raw NanoVG保持现有分辨率模式 |
| Feedback.lua / Storage.lua | 实际统计、场景记录命名空间 | 样板胜利不发原章节解锁，Web持久化仍独立待验 |

可以在 scripts/defense/ 新增 TowerModules、RoomGraph、Expedition 等纯 Lua 模块以缩短现有 Combat；名称为建议。它们由 Run 驱动，不创建第二个事件时钟或引擎单例。

## D03 提交次序与事务

沿用合法性 → 空间/遮挡 → 位移/状态 → 伤害 → 死亡/反应 → 波次/据点 → 失败优先 → 反馈。

在敌人伤害提交前调用远征策略过滤，输出 requested/actual/suppressed/reason。预算扣减与 HP 改变在同一提交中完成；后续系统统一读取 actual。每帧远征阶段更新保持稳定顺序，预算耗尽可立刻标记 LEAVING，禁止后续同帧事件继续扣旧预算。

模块选择、安装、更换、房间领奖、考验开门分别有幂等键；实体死亡仍按实体和副作用域去重，不能用 root_action_id 合并不同死亡奖励。暂停/结束/重试时清理当前场景的待选、路线和事务；已提交局外记录按原规则保留。

## D04 事件和快照

| 候选事件 | 必需负载 | 含义 |
| --- | --- | --- |
| ModuleOffered / ModuleChosen | room_id、choice_id、合法候选 / module_id | 区分首次领奖与能力选择 |
| ModuleInstalled / ModuleChanged | tower_id、before/after、费用、request_id | 成功结果；失败走 TransactionResolved |
| DefenseSiteAvailable / GateOpened | room_id / gate_id、原因 | 清空授权与考验物理开门分别表达 |
| ChallengeAnnounced | wave_id、route_id、stop_ids、special_count | 为玩家提供实际配置的预告 |
| ExpeditionStageChanged | entity_id、route_id、index、before/after、current_room_id、reason | 不表示死亡或掉落 |
| RoomDamageBudgetChanged / DamageCapped | entity_id、room_id、cap、used、actual、suppressed、reason | 显示真实承伤或被拒原因 |
| ExpeditionPathError | entity_id、waypoint、最后合法位置、恢复次数 | 技术失败证据，不触发正常胜利 |

事件共同带 run_id、event_id、模拟时间；伤害与效果延续 source/target_id、parent_event_id、root_action_id。Snapshot 提供复制后的路线状态、库存、房间部署和预算，只读展示不暴露可改世界引用。

## D05 旧版兼容

legacy_v02 继续验证原20行与1176单位、15秒基础战备及清波奖励公式。扩展场景先做通用结构校验，再校验其声明的普通/特殊总数；不删除原夹具以让新配置“通过”。

reuse_sample 保持完整20行配置输入，用现有 total_waves=5 样板路径；在第5波附加特殊单位。large_map_proto 使用显式扩展配置及完整终局。只有声明可结算章节的正式场景能更新其专属记录，不能仅凭 total_waves==20 入账原章节。

存储继续仅保存既有局外记录及设置；本次本局模块/塔/路线不自动持久化。旧记录迁移若需要，须有 schema_version、旧数据夹具和命名空间验证；不触碰旧幸存者 profile。
