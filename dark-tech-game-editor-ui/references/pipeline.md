# 界面素材生成与落地管线

> **这份解决什么**：[`elements.md`](elements.md) 教你画「界面结构」，但界面里那些**像素图标、字标、徽章、面板贴图**从哪来、怎么保证同一套色、怎么进包、怎么显示不糊——本文件把它固定成一条可复用的流水线。
>
> 上游产图方法论在 skill `0718-pixelimage-aigc`（AI 草案 → 后处理 → 母版 PNG）。**本文件是它落到本风格界面上的接线图**：色板怎么接、母版多大、UUID 怎么给、代码怎么加载、显示几倍。
>
> 本文件只讲「界面素材」。角色序列帧走 `sprite-gen`，3D 贴图烘焙走 `bake-voxel-pbr`。

---

## 0. 先分清三类素材，走三条不同的路

界面上会出现三种「像像素图的东西」，**处理方式完全不同**，先归类再动手：

| 类型 | 例子 | 从哪来 | 显示方式 |
| --- | --- | --- | --- |
| **A. 像素图标 / 徽章** | 道具图标、状态图标、货币图标、天赋图标 | AI 生图 + 0718 后处理 | 母版 32×32，**1× 最近邻**（或 2×） |
| **B. 像素字标 / 大图** | 游戏标题 logo、章节大字 | AI 生图 + 0718 后处理（非方形） | 按内容等比裁到固定**高**，1× 最近邻 |
| **C. 程序化绘制** | 面板壳、按钮、进度条、装饰花纹 | **不生成图片**，NanoVG 直接画 | 矢量，任意尺寸 |

> **默认优先 C。** 只有「一个具体的物」（炸弹、护盾、奖章）或「一段艺术字」才值得做成 A/B 的贴图。面板、边框、进度条、装饰线**一律程序化绘制**——它们是几何，不是素材；做成贴图反而不能适配尺寸、颜色也改不动。
>
> 判据：**这个东西能不能用「一个函数 + 几个数字」画出来？** 能，就走 C。画不出（要画炸弹的引信、奖章的绶带），才走 A。

## 1. 色板：界面素材必须锁进同一套项目色板

本风格的界面令牌（[`tokens.md`](tokens.md)）是**唯一的颜色来源**。AI 生图会自带一套漂移的颜色，**必须**在后处理阶段量化到项目色板，否则同屏图标之间「差不多的青」会各说各话。

本项目实际锁定的 8 色（= `tokens.md` 的核心色板 + 高光），界面素材**只准用这 8 色**：

```text
#10131F  轮廓（近黑，不是纯黑）
#252A3A  深影
#555B6C  金属暗
#9FA6B3  金属中
#F1EEF0  高光
#00E5D0  品牌青（= cyan）
#009694  青暗（= cyanDim）
#FFC448  警示金（= warn，只给货币/稀有/高亮）
```

规则：

- **一张图 ≤ 9 个可见色**（含透明，上表 8 色 + 透明 = 9 是硬上限）。
- **外轮廓统一用 `#10131F`**，不要每张图各自定轮廓色。
- **青色只出现在「有意义的当前状态」**——一个炸弹图标本身不该是青的，青留给「已选中 / 可领取 / 进度」。
- 金色面积要克制：它是 `warn`，给货币和稀有度，**不要**整张图铺金。

> ⚠️ **反例（本项目真实教训）**：早期 26 张 `ui_icon_*`（炸弹/冰冻/护盾/任务/图鉴/排行…）是 AI 原图**直接缩到 32×32**，实测每张有 **100–583 种颜色**——不是像素画，是「缩小的插画」。而同项目 v0.12.9 之后按本管线走的图标是 **8–9 色**。同屏并列时前者明显更「糊、脏、不像一套」。**这就是「AI 原图不能直接进资源」的代价，只能重出。**

## 2. 母版尺寸与显示倍率

母版 = 生成与量化的目标尺寸；运行时按**整数倍**最近邻显示。

| 界面用途 | 母版 | 显示 | 说明 |
| --- | --- | --- | --- |
| 道具 / 状态 / 货币图标 | 32×32 | **1×（32px）** | 本项目全部图标统一 32×32 |
| 列表 / 标签小图标 | 32×32 | 1× | 不要为小尺寸另出母版，直接缩小显示会糊 |
| 天赋 / 升级卡图标 | 32×32 | 1× | 与局内道具同源，保证「一个图标语言」 |
| 像素字标 / 大标题 | 高 120（宽按内容） | 1× | **非方形**，见 §3 |
| 面板 / 按钮 / 9-slice | — | — | 不生成图片，程序化画 |

**硬约束**：

- **显示尺寸 = 母版尺寸 × 整数倍**。32×32 母版可以显示成 32、64、96；**不能**显示成 40。
- **禁止反向缩放**（母版比显示尺寸还小）。
- 加载必须 **最近邻过滤**，默认线性过滤会让像素图糊掉（见 §5）。
- 图标**不要内置外框、不要内置稀有度边框、不要写文字数字**——框、角标、文字由 UI 层单独绘制（见 §6）。

## 3. 字标（非方形）的特殊处理

游戏标题 logo 这类**非方形**大图，不能套用方形的后处理脚本（`0718` 的 `postprocess.py --master` 只支持正方形）。做法：

1. 生成时给足宽度（如 1344×768 草案）。
2. **包围盒裁切**掉四周空白。
3. **等比缩到固定高度**（本项目 = 120），宽度随内容浮动（实测 207–264 不等）。
4. alpha 二值化 + 色板量化（同 §1）。
5. 运行时**逐图记下各自的宽**，居中绘制——**不要**把不同纵横比的字标硬塞进同一个矩形。

```lua
-- 每张字标记自己的显示宽度，1× 最近邻居中
local LOGO_PATHS = {
    { path = "image/ui_logo_a.png", w = 207 },
    { path = "image/ui_logo_b.png", w = 235 },
    { path = "image/ui_logo_c.png", w = 244 },
    { path = "image/ui_logo_d.png", w = 264 },
}
local LOGO_H = 120
local lx = (screenW - logo.w) * 0.5
-- nvgImagePattern(ctx, lx, 90, logo.w, LOGO_H, 0, logo.img, 1)
```

字标**可以**融合玩法元素（本项目 4 张字标分别嵌了弹道击碎字、8bit 敌机、砖墙裂纹），因为它承担「游戏身份」，和 §1 的克制原则不冲突——但**图标不要**这么干。

## 4. UUID：进包的通行证

每个 PNG 资源必须配一个**同名 `.meta`** 文件，内容是一个**全库唯一**的 uuid，否则构建不会把它打进资源清单。

```json
{ "uuid": "4bV9YZyoJsTkvgxLY0siTx" }
```

要点：

- **文件名 = 图名 + 时间戳**（如 `ui_icon_bomb_20260928005024.png`），`.meta` 与之同名加 `.meta`。
- uuid 形态在本项目**出现过两种**：22 位 base62（`4bV9YZyoJsTkvgxLY0siTx`）和 22 位 hex（`ba2bd2eb9f4d9d7694a5c0`）。**跟随同批次已有资源的形态**，不要自己造第三种。
- **交付前验重**：`grep -ho uuid assets/**/*.meta | sort | uniq -d` 必须为空。
- 构建后**查 manifest**确认文件名真的进包（别只看源目录）。

## 5. 运行时装载（NanoVG）

### 5.1 注册一次，句柄复用

```lua
-- 只在 Init / Start 里创建一次；返回值 <= 0 表示失败
local img = nvgCreateImage(vg, "image/ui_icon_bomb.png", NVG_IMAGE_NEAREST)
```

- **`NVG_IMAGE_NEAREST` 必须显式给**。默认线性过滤 = 像素图糊成一团。
- 路径从资源根算起，**不要加 `assets/` 前缀**（`image/...` 而不是 `assets/image/...`）。
- 句柄存进表里复用，**不要每帧创建**（漏显存）。

### 5.2 图标表 + 统一绘制函数

```lua
local ICON_PATHS = {
    bomb  = "image/ui_icon_bomb_20260928005024.png",
    gem   = "image/ui_icon_gem_20260928005033.png",
    -- ...
}
---@type table<string, integer>
local iconImages_ = {}

local function LoadIcons()
    iconImages_ = {}
    for key, path in pairs(ICON_PATHS) do
        local ok, img = pcall(nvgCreateImage, vg_, path, NVG_IMAGE_NEAREST)
        if ok and type(img) == "number" and img > 0 then iconImages_[key] = img end
    end
end

-- 统一入口：缺图返回 false，调用方回退到程序化绘制
DrawIcon = function(ctx, key, x, y, size, alpha)
    local img = iconImages_[key]
    if not img then return false end
    nvgBeginPath(ctx)
    nvgRect(ctx, x, y, size, size)
    nvgFillPaint(ctx, nvgImagePattern(ctx, x, y, size, size, 0, img, alpha or 1))
    nvgFill(ctx)
    return true
end
```

> `nvgImagePattern` 而不是直接贴图，是为了能吃到 `nvgRoundedRect` 的圆角裁剪、以及按 alpha 变暗（锁定态）。

### 5.3 三铁律

1. **图标是可选资源**：某张缺图只能让该处**回退程序化绘制**，**绝不能**让整个后端 `Init` 失败——否则表现为「UI 全没 + 卡死」。
2. **`LoadIcons` 里用 `pcall`**，单张失败不影响其它。
3. **锁定/禁用态用 alpha 压暗**（本项目 0.28–0.86），**不要**换一张「灰色版图标」。

### 5.4 图标表的死键检查

`ICON_PATHS` 是字符串键表，`#` 恒为 0，**必须手动计数**：

```lua
local total = 0
for _ in pairs(ICON_PATHS) do total = total + 1 end
print(("[UI] icons loaded=%d/%d"):format(loaded, total))
```

**每个 key 都要有绘制点**。本项目实测有 5 个 key（`gem`/`wheel`/`supply`/`pass`/`boost`）**被加载却从未 `DrawIcon`**——白占显存、还让人误以为「这图在用」。交付前对每个 key grep 一次调用点；没有调用点的，要么接上、要么删掉。

## 6. 图标与「框」分离

图标本身**只有主体**；下面这些**全部由 UI 层画**，不要烙进图里：

| 元素 | 谁来画 |
| --- | --- |
| 图标底板（暗色圆角块） | UI 层 `Box` |
| 稀有度 / 类型描边 | UI 层 `StrokeBox`（取语义色） |
| 选中高亮、锁定变暗 | UI 层（alpha / 叠加） |
| 数量角标、`×N`、锁定标记 | UI 层文字 |
| 状态辉光 | 独立特效层，**不要**画进常驻图标 |

```lua
-- 升级卡图标：先画底板与描边，再叠图标
DrawRect(ctx, iconX - 6, iconY - 6, iconSize + 12, iconSize + 12, C.rail, 8)
DrawStroke(ctx, iconX - 6, iconY - 6, iconSize + 12, iconSize + 12,
    {accent[1], accent[2], accent[3], 120}, 8, 1)
if not DrawIcon(ctx, iconKey, iconX, iconY, iconSize, 1) then
    DrawPixelText(ctx, cx, iconY + 4, (name or "?"):sub(1, 1), 24, C.text, ALIGN_CENTER)
end
```

**同一个图标键要在多个界面复用**（局内道具槽 / 升级卡 / 天赋树都用同一套），保证「一个图标语言」。

## 7. 全流程清单（从需求到进包）

```text
1. 分类        这个界面元素是「具体的物/艺术字」（→ 素材）还是「几何」（→ 程序化）？
2. 定规格      母版尺寸（图标 32×32 / 字标高 120）、主体包围盒、≤9 色
3. 生图        AI 草案（高分辨率），元素/类型分批，每批 ≤10，先出 3–4 张样片
4. 后处理      包围盒裁切 → 等比缩到母版 → alpha 二值化(128) → 项目色板量化
               （方形走 0718 的 postprocess.py；非方形字标手写脚本）
5. 验色        每张 ≤9 色、外轮廓 #10131F、青色/金色克制
6. 落盘        命名 {type}_{id}_{时间戳}.png + 同名 .meta（唯一 uuid）
7. 验重        grep uuid 查重；草案移出 assets（别占包体）
8. 接代码      加进 ICON_PATHS → LoadIcons（NEAREST + pcall）
9. 画          底板/描边/角标由 UI 层画；缺图回退程序化
10. 验收       构建 manifest 有文件；真机截图看图标清晰度与同屏一致性
```

## 8. 常见失败与根因

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| 图标发虚、有灰边 | 加载用了线性过滤；或 alpha 未二值化 | 改 `NVG_IMAGE_NEAREST`；后处理做 alpha 阈值 |
| 放大后有半透明脏边 | alpha 二值化缺失 | alpha < 128 → 0，否则 → 255 |
| 同屏图标颜色不统一 | 未做色板量化 | 后处理映射到项目 8 色 |
| 图标有的偏大有的偏小 | 未做包围盒归一 | 后处理按目标主体尺寸归一 |
| 缩到 32 后糊成一团 | AI 草案是平滑插值伪像素 | 后处理第 1 步核验，不合格重生成 |
| 字标被横向拉长 | 非方形字标硬塞进固定矩形 | 逐图记宽、等比显示 |
| 某图标在真机上是空白 | `.meta` 缺失 / uuid 重复 → 未进包 | 补 `.meta`，验重，查 manifest |
| 图标显示尺寸不是整数倍 | 用了 40 这类非整数显示 | 改 32 / 64 / 96 |
| 面板边框被拉伸变形 | 把「完整成品」当 9-slice 切 | 见 `0718-pixelimage-aigc` 的 9-slice 章节 |
| 加载了一批图标但界面没变化 | `ICON_PATHS` 有死键 / key 拼错 | 逐 key grep 调用点 |
