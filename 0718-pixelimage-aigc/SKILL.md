# 像素素材 AI 生图流水线

把「参考作品视觉语言 → 规格与色板 → AI 草案 → 后处理 → 验收」固定成一条可复用流水线。
产出是**游戏可直接加载的最终 PNG**，不是 AI 原图。

## 铁律

1. **AI 原图只是草案，永远不能直接进资源目录。** 高分辨率生成图必然带抗锯齿、颜色漂移、主体占比失控、轮廓粗细不一、透明边缘残留半透明像素。必须过后处理（§4）才能交付。
2. **先定规格，再生图。** 母版尺寸、主体包围盒、色板、用色数量上限必须在生成前锁定；否则每张图自由发挥，批量一致性无从谈起。
3. **整数倍最近邻，禁止非整数缩放。** 最终图只能按 1×/2×/3×/4× 显示（§5）。
4. **参考作品只提炼高层视觉特征，不复制具体资产。** 不得复制角色、Logo、道具造型、具体构图，也不得把自拟 HEX 冒充原作官方色板。
5. **证据分级必须标注。** 每个尺寸/色值结论都要标明是【实测】【推断】还是【项目建议】（§2）。

## 何时用 / 何时不用

| 任务 | 用哪个 |
| --- | --- |
| 卡牌/状态/元素图标、投射物、命中特效、UI 图标、边框、9-slice、背景 | **本 skill** |
| 角色动作序列帧、精灵表、图集 | `sprite-gen` |
| 3D 模型 PBR 材质、方块纹理离线烘焙 | `bake-voxel-pbr` |
| UI 布局、组件主题、界面配色 | `ui-pixelforge` / `ui-astroon` / `dark-tech-game-editor-ui` |

本 skill 只管**图像资产本身**，不规定玩法逻辑，也不规定 UI 如何摆放。

## 1. 输入契约

开工前必须拿到以下字段。缺 `asset_type`、`primary_group` 或 `usage` 时**禁止直接批量生成**——先补齐。

```text
asset_id       资产唯一 ID，如 L1、status_frozen、button_primary
asset_type     card_icon / status_icon / element_icon / rarity_icon /
               projectile / impact_fx / ui_icon / frame / window_frame /
               badge / chrome_9slice / background
subject        主体，如 雷球、冰锥、护盾、铁砧
primary_group  lightning / water / fire / grass / neutral / trash（非元素类可省）
usage          battle / inventory / forge / detail / overlay / menu
quantity       单张或批量数量
animation      static 或帧数（序列帧另见 sprite-gen）
```

## 2. 参考依据与证据分级

分析参考作品时，每条结论都要打标签：

| 标签 | 含义 | 可否称为原作规范 |
| --- | --- | --- |
| **【实测】** | 能从官方截图直接观察/统计 | 只能描述为「截图特征」 |
| **【推断】** | 由比例、周期、结构合理推导 | 必须写明「不确定」 |
| **【项目建议】** | 为本项目适配而定 | **不得**称为原作规范 |

严禁：
- 把自拟 HEX 说成「某作官方色板」；
- 把项目母版尺寸说成「某作源图尺寸」；
- 只分析一款作品就代表整个风格家族；
- 从 JPEG 截图单个像素宣称精确原色；
- 没有源文件却断言所有图标共用同一画布。

**跨作品分析的正确做法**：先找共同骨架（像素节奏、轮廓、色块数、图标密度），再找差异（底色、框体、特效强度），最后明确本项目融合哪一作的哪一面。范例见 `references/pipeline.md`。

### 2.1 从截图提炼视觉语言

提取的是**结构**，不是像素：

1. 量像素周期（截图放大找规律边界，如 4px 周期 → 推断低分辨率逻辑画布 + 整数倍显示）；
2. 统计轮廓色（通常是近黑或深蓝黑，而非纯黑）；
3. 统计色块数量（优秀像素图标多数 ≤ 9 种可见色）；
4. 观察高光占比（通常 < 10% 非透明像素）；
5. 观察主体占比（图标主体不填满容器，四周留白）。

## 3. 规格与色板

### 3.1 母版尺寸

母版 = 生成与量化的目标尺寸；运行时再整数倍放大。

| 类型 | 建议母版 | 主体包围盒 | 安全边距 |
| --- | --- | --- | --- |
| 卡牌图标 | 64×64 | 44–52 px | 4 px 透明边 |
| 状态图标 | 32×32 | 22–26 px | 3 px |
| 元素/稀有度图标 | 24×24 | 16–20 px | 2 px |
| 投射物 | 64×64 | 细长，最长边 ≤ 56 px | 4 px |
| 命中特效 | 48×48 | 可接近边缘（峰值帧） | 2 px |
| UI 图标 | 32×32 | 20–26 px | 3 px |
| 徽章/小底板 | 按用途（如 32×36） | 填满（本身是底板） | 0–2 px |
| 9-slice chrome | 48×48 源 | 端帽+螺栓不拉伸 | — |
| 背景底图 | 按屏幕（如 720×1280） | 低对比、留负空间 | — |

> 上表是【项目建议】量级。换项目按自己的槽位尺寸换算，但**主体不填满画布、保留透明边**这条不变。

**关键换算**：先确定运行时槽位尺寸，再倒推母版，保证 `source_px : display_px` 是整数比。
例：槽位 112px、想显示 64px → 母版 64，1×；想显示 72px 且母版 24 → 3×。

### 3.2 色板

**共享中性色**（所有图标共用，保证系列一致）：

```text
外轮廓   #10131F   近黑（不是纯黑，纯黑会显得脏）
深影     #252A3A
金属暗   #555B6C
金属中   #9FA6B3
高光     #F1EEF0
```

**元素色阶**（每属性 4 级：暗 / 中 / 亮 / 高光）：

```text
雷  #3A2466 / #7650B8 / #B77CFF / #F0D9FF
水  #164E70 / #2E91C9 / #71CDFF / #D8F5FF
火  #6B2C24 / #C4512B / #FF8E42 / #FFE08A
草  #234E38 / #4F8E4C / #89E05D / #DDF6A0
无  #343847 / #747B8C / #DCE1EA / #FFFFFF
垃圾 #2B2930 / #59535E / #92858A / #C2B5B0
```

> 以上 HEX 是【项目建议】，不是任何参考作的官方色板。换项目替换整套，但**保留「4 级色阶 + 统一轮廓色」结构**。

**单图用色上限**：

```text
透明 + 中性色 2–4 个 + 主元素色 3–4 个  ≈ 6–9 个可见色
```

硬约束：
- 最外轮廓统一用共享轮廓色；
- 主元素占彩色像素 ≥ 70%，辅助元素 ≤ 30%；
- 最高亮色面积 ≤ 非透明像素 10%；
- 禁止柔性渐变、禁止抗锯齿半透明边缘、禁止 AI 自由添加相近中间色；
- 发光用离散像素环或独立特效层，不烙进常驻图标。

### 3.3 背景与图标分离

卡牌/UI 图标一律：**透明背景、不内置外框、不内置稀有度边框、不写文字数字、不把状态辉光画进去**。
属性底色、稀有度边框、选中高亮、HP 角标由 UI 层单独绘制。

## 4. 生成与后处理

### 4.1 提示词模板

基础段（每个 prompt 都要有）：

```text
pixel art, 16-bit retro, hard pixel edges, no anti-aliasing,
finite color palette, crisp dark outline,
transparent background, centered subject,
{canvas ratio, e.g. 48x48 subject on 64x64 canvas},
no text, no numbers, no frame, no soft gradient, no blurry glow,
{主体描述}, {视角与方向}
```

元素附加段：

```text
雷：紫色电能核心，分叉闪电轮廓，少量淡紫高光
水：青蓝液体或冰晶，冷色高光，流线或棱角清晰
火：橙红火焰核心，黄色热点，上升尖角轮廓
草：深绿结构，亮绿生命能量，藤蔓或孢子剪影
无属性：冷灰金属或石质结构，少量白色高光
垃圾：低饱和灰紫褐，破损不规则剪影，禁止鲜亮主色
```


参考作品只写高层特征，如「reminiscent of <作品> 的紧凑高信息密度图标与深色硬轮廓」，**不要**写「复制某角色」。

### 4.2 批次组织

禁止一次混合全部元素。按元素/类型分批，每批 ≤ 10 张（`batch_generate_images` 上限），每批**先生成 3–4 张样片，通过后再扩展**。

```text
批1  元素基础图标
批2  同元素普通卡
批3  同元素高稀有卡
批4  状态图标
批5  战斗特效
批6  UI 图标 / 边框 / chrome
批7  背景底图
```

同一批必须锁死：母版尺寸、主体包围盒区间、轮廓色、元素色板、光照方向（固定左上主光）、视角、生成模型、基础 prompt、seed。

**seed 策略**：`seed = 基础值 + 轮次`（如 42、43、44…），同批内保持一致以便复现与回归对比。

### 4.3 后处理管线（7 步，缺一不可）

高分辨率草案 → 最终母版：

```text
1. 像素核验      检查草案是否真有硬像素块；纯平滑插值的图直接弃用重生成
2. 方形裁切      裁成正方形，主体居中
3. 缩放          高质量降采样到母版尺寸（LANCZOS），再进入下一步二值化
4. alpha 阈值    透明图：alpha < 阈值 → 0，否则 → 255（消灭半透明抗锯齿边）
                 例外：命中特效等需要层次 alpha 的类别保留渐变（--keep-alpha）
5. 色板量化      每个非透明像素映射到最近的「项目色板」颜色（欧氏距离）
6. 包围盒归一    计算非透明包围盒，按目标主体尺寸等比缩放并重新居中
7. 最近邻导出    按整数倍导出运行时尺寸并生成预览图
```

**为什么每一步都要**：
- 第 1 步：AI 常给出「看起来像像素」但实为平滑渐变+锐化的图，缩小后一塌糊涂；
- 第 4 步：不二值化，运行时最近邻放大后边缘带一圈半透明灰边，深色底上非常脏；
- 第 5 步：不量化，不同批次颜色会漂移（同一「火」偏橙/偏红），系列看起来不统一；
- 第 6 步：不归一，图标有大有小，同槽位显示时大小不一。

第 3–7 步可直接用附带脚本 `scripts/postprocess.py`（§7）。

### 4.4 批量一致性锁

同一系列交付前逐项核对：母版相同、主体包围盒接近（面积偏差 ≤ 20%）、轮廓色相同、色板相同、光照方向相同、视角相同。

## 5. 运行时装载（简述）

后处理完的 PNG 要被游戏正确显示，注意：

- **加载必须用最近邻过滤**。多数 UI 库默认线性过滤，像素图会糊。加载时显式指定 nearest（NanoVG 为 `nvgCreateImage(nvg, path, NVG_IMAGE_NEAREST)`），不要走默认平滑路径。
- **完整成品图禁止几何拉伸**。含端帽/螺栓/斜切边的完整按钮、Logo、面板框，控件尺寸必须等于源图尺寸或**整数倍等比**最近邻缩放；要别的尺寸就重出该尺寸成品，或改用明确设计为 9-slice 的素材。
- **9-slice 切片必须给对源图尺寸**。切片参数（四边内缩）与「源图真实宽高」是两回事；把目标控件尺寸当成源图尺寸去采样会切错区域，表现为整图被横向粗暴拉伸。**源图尺寸写错是这类 bug 的头号原因**。
- **槽位与图标用整数倍**，禁止反向缩放（源图比显示尺寸还小）。

> UI 布局、主题、组件细节走 `ui-*` skill 或 `engine-docs/recipes/ui.md`；这里只强调「像素图不能被平滑、不能被非整数缩放」。

## 6. 验收清单

### 6.1 文件
- [ ] PNG，透明类为透明背景；
- [ ] 尺寸等于母版规格，或已注明特殊特效尺寸；
- [ ] 命名符合 `{type}_{id}_{variant}.png`；
- [ ] 无文字、数字、外框；
- [ ] 无半透明抗锯齿边（特效类除外）；
- [ ] 不含参考作具体角色或标志。

### 6.2 尺寸
- [ ] 主体包围盒落在目标区间；
- [ ] 至少保留规定透明边距；
- [ ] 系列内主体面积偏差 ≤ 20%；
- [ ] 视觉中心偏差 ≤ 1 px；
- [ ] 所有预览/导出使用最近邻。

### 6.3 颜色
- [ ] 外轮廓为统一轮廓色；
- [ ] 可见色 ≤ 9 种；
- [ ] 颜色全部属于共享中性色或目标元素色板；
- [ ] 主元素占彩色像素 ≥ 70%；
- [ ] 高光面积 ≤ 约 10%；
- [ ] 无未批准的新中间色；
- [ ] 常驻图标无模糊辉光。

### 6.4 游戏内
- [ ] 母版原尺寸下剪影仍可辨认；
- [ ] 全部涂黑后，同系列图标仍能区分（剪影测试）；
- [ ] 不同使用位置（战斗/背包/详情）显示大小一致；
- [ ] 在真实背景色上对比充足；
- [ ] 选中/命中/高亮来自独立特效层，而非烙进图标。

### 6.5 交付前必须能回答
1. 哪些结论是【实测】？哪些是【推断】？哪些是【项目建议】？
2. 同系列主体包围盒是否接近？
3. 是否真的用了同一锁定色板，而不只是「看起来像」？
4. 全部变黑后剪影还能区分吗？
5. 母版原尺寸下还清晰吗？
6. 有没有无意复制参考作品的具体资产？

任一关键问题答不上来，素材不得进正式资源目录。

## 7. 附带脚本

`scripts/postprocess.py` —— 后处理管线第 3–7 步，批量处理一个目录的草案。

```bash
python3 scripts/postprocess.py \
  --input  <草案目录> \
  --output <输出目录> \
  --master 64 \
  --subject 48 \
  --palette references/palette-project.json \
  --alpha-threshold 128 \
  --scales 1,2,3
```

- `--master` 母版边长；`--subject` 目标主体包围盒边长；
- `--palette` 色板 JSON（默认项目色板，见 `references/palette-project.json`）；
- `--alpha-threshold` 透明图二值化阈值；`--keep-alpha` 保留层次 alpha（命中特效用）；
- `--scales` 导出哪些整数倍预览；
- 输出：母版 PNG + 各整数倍预览 + `report.json`（每张图的包围盒、用色数、是否超限）。

脚本会在报告中标出**不符合规格的图**（用色超限、主体过大过小、半透明残留），便于批量筛选。

```text
【颜色】共享中性色 / 元素色板 / 最大可见色数

【验收】尺寸 / 颜色 / 剪影 / 游戏内截图
```
